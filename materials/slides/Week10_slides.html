Limits

What Agents Cannot Take Over

Plausibility

Is 283 m3/s believable for this river? The agent does not know Iowa.

Units and data

Whether a column is cfs or m3/s, trustworthy or corrupted.

The claim

Whether a result supports a scientific statement. That is yours.

The line to remember: agents manipulate code; you own the science.

The Workflow

Reference Answers Come First

# BEFORE any agent touches anything:
reference_monthly = stream.assign(
    month=stream["date"].dt.to_period("M")
).groupby("month")["discharge_cfs"].mean()

# AFTER any refactor:
np.allclose(refactored_monthly, reference_monthly)   # must be True
  • Compute trusted numbers with code you fully understand
  • Every AI-assisted edit must reproduce them exactly

The Workflow

Seven Steps, Every Time

1

Inspect

Agent reads and summarizes. No edits.

2

Plan

Agent proposes; you approve scope.

3

Small change

One edit at a time, run after each.

4

Verify + log

Compare to reference, sanity-check one number, record in the AI log.

Earth & Environmental Computing | Week 10 | 16
Failure Gallery

How Generated Code Fails in Practice

The confident invention

A function that almost exists: pd.read_hydrograph(). Plausible name, no such thing.

The silent assumption

Paths, column names, or units assumed from context and assumed wrong.

The plausible constant

A conversion factor that looks right and is off by ten. Only your anchor catches it.

None of these raise errors on their own. Verification is the only net.
