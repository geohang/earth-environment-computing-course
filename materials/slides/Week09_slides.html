02 · Pseudocode

The Centered Window, Drawn

Twelve days, a 5-day window (half = 2). Red: the day being smoothed. Pink: the days averaged for it. Near the ends the window shrinks, so those values rest on fewer days; that shrinking is an edge policy, chosen in the pseudocode.

02 · Pseudocode

The Centered Moving Average, in English

Pseudocode

for each position i in the series:
    start = i minus half the window (not below 0)
    end   = i plus half the window (not past the end)
    output[i] = mean of values from start to end
  • Lines 2 and 3 hold the placement: half the window on each side
  • The two parentheses hold the edge policy: shrink, do not pad
  • Both partners agree on these four lines before anyone types Python
Pause and think

?

Rewrite the pseudocode for a trailing window. Which lines change?

start = i minus (window − 1), not below 0
end = i: the window sees only today and the past
03

Window Placement

From English to a loop, and why the timing of a window is science.

03 · Window placement

From Pseudocode to Python

Python

def moving_average_centered(values, window):
    half = window // 2
    out = []
    for i in range(len(values)):
        start = max(0, i - half)
        end = min(len(values), i + half + 1)
        out.append(np.mean(values[start:end]))
    return np.array(out)

print(moving_average_centered(np.array([1., 2., 3., 4., 5.]), 3))

Output

[1.5 2.  3.  4.  4.5]
  • max and min are the edge policy from the pseudocode, written down
  • The + 1 is there because a slice stops before its end
  • Five numbers you can check by hand: the middle must be 3.0

Four Problems, Named

def moving_average_draft(values, window):
    half = window // 2                         # 3
    out = np.zeros(len(values))                # 2
    for i in range(half, len(values) - half):  # 2
        out[i] = values[i - half:i + half].mean()  # 1
    return out
                                               # 4

Problems 1 and 3 are arithmetic; 2 is an edge policy nobody chose; 4 is why the other three survived. The largest error inside the record is 1,133 cfs, and 6 edge days read 0 cfs.

2Edge days left at 0 cfs, which reads as a dry rivershrink or NaN
3Any window accepted; an even one has no middle dayValueError
4Checked by eye on a 4,018-day plotassert

A Trusted Twin on 4,018 Days

Python

mine = moving_average_centered(flow, 7)

           .rolling(7, center=True, min_periods=1)
           .mean().to_numpy())
print("largest difference:", np.max(np.abs(mine - trusted)), "cfs")

Output

largest difference: 1.4210854715202004e-14 cfs
agree: True
  • Two independent implementations agree to 1e-14 cfs, rounding error
  • min_periods=1 makes pandas shrink at the edges, as our loop does
  • Agreement is evidence because the two were written separately

05 · Verification

Faster Code Needs the Same Checks

Python

import timeit
q = stream["discharge_cfs"]
tasks = {
    "loop": lambda: moving_average_centered(flow, 15),
    "pandas": lambda: q.rolling(15, center=True, min_periods=1).mean(),
    "convolve": lambda: np.convolve(flow, np.ones(15) / 15, mode="same"),
}
for name, task in tasks.items():
    ms = 1000 * min(timeit.repeat(task, number=1, repeat=5))
    print(f"{name:>8}: {ms:6.2f} ms")

Output

    loop:  12.73 ms
  pandas:   0.11 ms
convolve:   0.14 ms
  • About 100 times faster, and 13 ms is still fine for 4,018 days
  • np.convolve is fast and pads with zeros: speed changed the edge policy
  • Make it right, then make it fast, then run the tests again

06 · Gap filling

Straight Line or Last Week's Mean?

Python

line, last_week = [], []
for s0 in np.linspace(31, len(flow) - 61, 20).astype(int):
    hidden = flow[s0:s0 + 7]
    with_gap = flow.copy()
    with_gap[s0:s0 + 7] = np.nan
    line.append(rmse(hidden, fill_gap_linear(with_gap, s0, 7)[s0:s0 + 7]))
    last_week.append(rmse(hidden, np.full(7, flow[s0 - 7:s0].mean())))
line, last_week = np.array(line), np.array(last_week)
print(f"straight line:    {line.mean():4.0f} cfs")
print(f"last week's mean: {last_week.mean():4.0f} cfs")
print(f"the line wins at {(line < last_week).sum()} of 20 positions")

Output

straight line:     292 cfs
last week's mean:  426 cfs
the line wins at 15 of 20 positions
  • Same 20 positions, two methods: a fair comparison
  • The line also sees the day after the gap; last week's mean cannot
  • It loses at 5 positions: no fill method wins everywhere

07 · Pitfalls

Where This Week Goes Wrong

  • The missing + 1 at the window's end
  • An even window passed to a "centered" function
  • Edge values read as if a full window supported them
  • A gap tested at one lucky position only
  • Filled values reported as data instead of flagged as estimated

Summary

Key Takeaways

  • One line of pandas hides placement, edges, and a missing-data policy
  • Pseudocode shows those decisions while they are cheap to change
  • Trailing windows delay peaks; centered windows can shift an uneven flood
  • Every edge policy is defensible; an unstated one is not
  • Verify three ways: tiny input, trusted twin, manufactured truth
  • Straight-line fills fail where it matters most: inside storms
